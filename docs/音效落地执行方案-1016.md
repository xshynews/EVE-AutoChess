> **10-18 补记（发牌音结构定稿 + 两条新语音）**：
> ① **发牌音 = 「一段音发一批牌 → 停一下 → 再一段」**（用户定稿；停顿 10-18 二次调参）：
>    入库脚本用 `burst = 4 / gap = 0.4 / tail = 0.5` 把洗牌音编成**一条** ogg
>    （内容 = 音 ×4 + 3 个 0.4s 静音 + 0.5s 收尾静音，实测 **4.0951s**）；
>    `ddz_table` 的动画同步**切 4 段**、每段发一批：**4-4-4-5 = 17**，
>    段内线性发牌、**发完之后（音尾 + 停顿）把进度钉住**（牌一张不动），
>    末段走完再停 0.5s 才叫地主。
>    ★ 10-18 二次调参（用户：「每段的发牌时间稍微慢了点…缩短 0.2 秒」）：
>      新增 `DEAL_SEG_DEAL = 0.398`（= 0.598 − 0.2）—— 牌在**一段音的前 0.398s**
>      就落完，剩下 0.2s 音尾 + 0.4s 停顿 = **0.6s 牌不动**（比原来更长 ⇒ 段落感只强不弱）。
>      ⛔ 音源没变、也不该去缩 `DEAL_SEG_SOUND`（那是洗牌音本身的长度，缩它要重编音源）。
>      ⚠️ 这次自检的「停顿里手牌保持不变」断言顺带抓出一个**浮点累加**的坑：
>      `_deal_t` 逐帧累加后会比段界多 1e-15 秒 ⇒ 段号提前翻格、下一批第一张牌被判成
>      "正在飞"而**僵在桌面中央整个停顿期**（纯视觉、不报错）⇒ 已用 epsilon 归零修掉。
>    ⛔ 上一版"拼 6 段无缝、段间没有停顿"被用户判为「并没有改」—— 已废弃。
>    ★ **停顿为什么从 0.1 改成 0.4**（这是"段落感"的关键，别再缩回去）：
>      0.1s 只占一段音的 17%，**眼睛抓不到** —— 连拍探针
>      `tools/probe_ddz_deal.gd`（把等间隔采样帧裁出手牌区、竖拼成一张接触印相）
>      实测：0.2s 采样下**每一行手牌张数都在涨**，看不出分段（用户原话
>      「我并没有感受到那种段落感」）。改成 0.4s 后「一段音 + 一次停顿」
>      凑成**整整 1 秒的节拍**，同一张探针出的图里出现三段「连着两行张数不变」
>      的停顿行 + 收尾长停顿，肉眼判定 = **分段明显**。总长 4.09s，
>      仍在用户给的上限（5s）内。
>    ⚠️ 音画同源：入库脚本的 burst/gap/tail 与表里的
>    `DEAL_SEG_SOUND / DEAL_SEG_GAP / DEAL_TAIL / DEAL_BURSTS` **必须一致**，
>    `DEAL_SEC` 由这四个数算出（⛔ 别手抄）；由「DEAL_SEC == 发牌音实测时长」断言守着。
> ② **两条新语音**：「**过**」与「不要」**共用逻辑名** `ddz_pass`（`_01` 不要 / `_02` 过）——
>    入库脚本新增**变体序号** `n`，而 `EveAudio._pick_variant()` 改为**随机但不与上一次重复**
>    ⇒ 两句**自动交替**（用户要的趣味性，牌桌侧零代码）；
>    「**我抢**」是独立键 `ddz_bid_rob`，规则 = **已经有人抢过地主**时下一个抢的人用它
>    （`_bid_cue()` 纯函数，判据 = 表态前的 `game.grabs > 0`），避免连着两声「抢地主」。
> ⚠️ 踩坑记录（写下来省得再踩）：PowerShell 的字符串里 `$burst:v` 会被当成

>    ffmpeg 收到 `concat=n==0:a=1` 直接报错。**必须写 `n=${burst}`**。

## 五、入库流程（拍板后 AI 执行）

1. 从 `user://ddz_sfx_picks.json` / 剪贴板读拍板映射
2. pipeline 脚本：候选 → 按事件映射重命名 `<逻辑名>_NN.ogg` → 落
   `assets/audio/sfx/` 或 `assets/audio/ambience/`（`_scan_dir` 自动收录）
3. 斗地主牌桌接线：`scripts/card/ddz/ddz_table.gd` 增加 `play_sfx(event)` 映射表
   （拍板表即映射常量，从试听台 EVENTS 搬走）
4. 自走棋 UI 接线：商店/锁定/卖出/合成/金币/受伤/胜负等调用点逐个挂
   `_audio.play_*`
5. 全部接线完成后把 `eve_audio.gd` 的 `SFX_ENABLED_DEFAULT` 置 `true`，
   并在设置窗挂「音效开关」
6. 验收：`tools/verify_audio.tscn`（53 条）+ `tools/verify_run.tscn`
   （14 条音频断言，`missing` 计数必须为 0）

## 八、附：BGM 无缝循环的调研出处（2026-10-17）

做斗地主 BGM（Start the Battle）时查的通行做法 —— 本工程据此取了
「**量节拍网格 → 在小节线切断 → 30ms 等功率交叉淡化 → 响度对齐**」这条路线：

| 结论（本工程的取法） | 出处 |
| --- | --- |
