## 1. 联机对战（本批新增，最大块）

| 层 | 文件 | 说明 |
| --- | --- | --- |
| 传输 | `scripts/net/eve_versus_transport.gd` | **TCP + 长度前缀帧**。弃用 ENet：headless 双进程下同一份代码、换到辅助脚本的方法里就永远停在 CONNECTING，最小化到 `create_server(port, 4)` 仍复现，机制未查明。自走棋是回合制，本来就不需要 ENet 的丢包/乱序容忍。 |
| 协议 | `scripts/net/eve_versus_net.gd` | 每人各持自己的 `EveRunState`，主机只同步「谁准备好 / 回合数 / 血量 / 掉线」。先用内存回环把协议跑通，再换真传输。 |
| 中继客户端 | `scripts/net/eve_udp_relay.gd` | 两端都主动连公网 UDP 中继，按 8 位房间码互转 —— **手机不能建 TUN，靠这一层也能当房主**。ENet 本身一行未改。 |
| 中继服务端 | `tools/relay_server.gd`（本地）、`tools/relay/eve_relay_server.js`（VPS） | 协议一致：`[EV][8 字节房间][1 字节身份][ENet 原始负载]`。只转发、不解析、不存数据。 |
| 零配置 | `scripts/net/eve_net_config.gd` + `net.cfg` | 读取顺序 `user://net.cfg`（现场覆盖）→ `res://net.cfg`（随包分发）。玩家看不到也填不到 IP，只交换房间码。 |
| 房间 | `scripts/ui/eve_versus_lobby.gd` + `scenes/versus_lobby.tscn` | 魔兽 3 那种座位表，空位可补电脑 AI（人机 = 补位，不是独立玩法）。 |

**回合时钟**：`EveMatchState.ROUND_TIME` 90 → **120**。这条时钟贯穿准备 + 战斗 + 结算，
而准备 30s + 战斗最长 60s = 90 ⇒ 打捞窗正好是 0 秒。120 给最坏情况留 30s。
顺带修了配对冻结：`make_pairings()` 原来每次调用重算，「HUD 显示 / 建队 / 结算」可能
是三个不同的对手；现在 `_pairs` 每回合算一次并冻结。

**准备最后 10 秒**：`scripts/ui/eve_round_countdown.gd` 屏幕中央大字倒数到 0 自动开战。
它不持有时间，唯一真相源是顶条计时器（自己再存一份会漂移，暂停时会出现「数字还在走」）。

## 2. 战列舰重做（四类 × 定位）

`scripts/core/eve_ship_database.gd` + `scripts/data/eve_ship_table.gd`：

- **抗性全归 0**（四类武器分布 `PROFILE_*` 保留）。理由：本作不能换弹种，抗性不产生玩法。
- **三层血量按「四类 × 定位」写死**，两张整数表：`BATTLESHIP_HP`（攻击型）/ `BATTLESHIP_HP_TANK`（防御型）。
  倍率会算出 218.5 这种半格血，表列与战斗永远差 1。
- **攻击型 / 防御型真的分开了**（用户原话：「攻击型攻击强防御弱，防御型防御强攻击弱」）：

| 四类 | 攻击型（血薄炮重） | 防御型（血厚炮轻） |
| --- | --- | --- |
| 普通盾抗 | 乌鸦 / 狂暴 220/320/190 = 730 · 80 DPS | 毒蝎 / 台风 250/370/220 = 840 · 70 DPS |
| 普通甲抗 | 万王 / 灾难 110/420/190 = 720 · 80 DPS | 多米 / 末日 125/485/220 = 830 · 70 DPS |
| 加强盾抗 | — | 鹏鲲 / 死亡漩涡 290/400/230 = 920 · 77 DPS |
| 加强甲抗 | — | 亥伯龙 / 地狱天使 175/520/230 = 925 · 77 DPS |

  战力口径 EHP × DPS：58400 / 58800、57600 / 58100 ⇒ **差 < 1%**，买哪档都不亏。

- **穿盾概率**（Sins of a Solar Empire 式）：`EveShip.shield_pierce`，每发独立掷一次，
  掷中就把这一发按 `armor → hull → shield` 解算（重排而不是跳过，甲/结构都空时伤害仍落回护盾）。
  档位 甲抗 > 盾抗、加强 > 普通：20% / 25% / 30% / 40%。未来「护盾击穿装备」就是把这一格拉高。
- **加强型刷新权重 0.7**（`SHOP_WEIGHT` + `pick_from_pool()`）：5 费池单艘占比
  普通 **9.3%** / 加强 **6.5%**（= 普通战列的 70%）。绝对份额到不了 10%/7%，
  12 艘必须合计 100%，只能等比缩 —— 被满足的约束是**比值**。
  1~4 费池一艘都不带权重，仍走原 `randi_range`，老种子序列不变。

| --- | --- |

| `EVE自走棋正式版V0.14.9.apk` | 195 MB |

打包过程踩到两个坑，已写进口令（避免下次重犯）：

1. **发布密钥库缺失**：preset 里 `package/signed=true` 但从未记录 keystore，CLI 导出直接失败。
   历史包（V0.14.6）实测签名证书 SHA-256 是 `db34b12b…`，正是 `%APPDATA%\Godot\keystores\debug.keystore`
   里那把 `androiddebugkey` ⇒ 显式写进 preset（口令 `android`），**保证老用户可覆盖安装**。
2. **MCP 插件注入的 autoload 被打进包**：`addons/godot_mcp` 在编辑器启动时把
   `autoload/MCPRuntimeProbe` 写进 ProjectSettings（不落 `project.godot`），导出时进了 `project.binary`，
   而 `exclude_filter` 又排掉了这个 addon ⇒ 启动报「Failed to instantiate an autoload」。
   修法：`exclude_filter` 保留 `addons/godot_mcp/runtime/`，其余 addon 文件逐个精确排除。
   ⛔ 注意 `include_filter` 在 `export_filter=all_resources` 下**不生效**，白名单救不回来。

验收：exe `--headless` 启动无报错；APK `apksigner` 校验通过（签名与历史一致）、
`aapt2` 读 `versionCode=17 / versionName=0.14.9`。

### 8.1 修「PC 版被防火墙拦截」（同日追加）

现象：玩家开 PC 包，Windows 弹「防火墙已拦截」。

根因：`EveAiBridge` 是 **autoload**，`_ready` 里无条件
`TCPServer.listen(9081, "127.0.0.1")`。Windows 只要看到进程建了 **TCP 监听口**
（哪怕只绑回环）就会弹防火墙授权框 —— 而这个端口是「让外部 AI 操作游戏」的开发工具，
玩家完全用不到，等于每次开游戏都被拦一次。

改法（`scripts/core/eve_ai_bridge.gd`）：

- `_bridge_enabled()`：编辑器里照旧自动开；**发布包默认不开**。
  需要用的时候给 `EVE_AI_BRIDGE=1` 或 `--ai-bridge` 才开。
- 每次启动把判定结果写一行到 `user://ai_bridge_state.txt`
  （`enabled / editor / env / argv`，以及 `listen_ok` 或 `listen_failed=<err>`）。
  ⚠️ 导出的 Windows 包是 GUI 子系统，**没有 stdout**，出问题时这是唯一的现场证据。

实测（导出的 exe，PID 存活，`Get-NetTCPConnection -LocalPort 9081` 查询）：

| 启动方式 | 监听 9081 | 状态文件 |
| --- | --- | --- |
| 双击 / 默认 | 无 | `enabled=false editor=false env= argv=[]` |
| `EVE_AI_BRIDGE=1` | 有 | `listen_ok=9081` |
| `--ai-bridge` | 有 | `listen_ok=9081` |

⚠️ 排查插曲：`--ai-bridge` 一度测不出来自监听 —— 原因是**上一次导出的包还没写进
这条改动**（CLI 导出把进度刷到 stdout，`| Select-Object` 截断后命令提前返回，
误以为导出完成）。导出日志务必重定向到文件再看 `exit=`，不要靠截断输出判断完成。
