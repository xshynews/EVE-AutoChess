# 炼狱经济补偿 + 舰船抽奖（2026-10-31）

> 玩家/用户原话（三条，全部**仅炼狱难度**）：
>
> 1. 「6-10 每关一星币奖励，11-15 加 2 星币，利息门槛降低一星币，仅适用于炼狱难度」
> 2. 「抽船 3 费以上舰船那个事件，添加所有种族的 2 星巡洋舰，不分定位，
>    也就是添加 12 艘 2 星巡洋舰进抽奖池」
> 3. 「抽船事件单独做一个抽奖窗口选抽取船事件，单独做一个抽奖窗口，下面会有一个许愿，
>    让你在可能的舰船中选，一星和二星舰船分开，选一个，如果真抽到了自己许愿的那个船，
>    就奖励舰船星币（二星舰船按一星舰船计价）」

---

## 一、为什么是炼狱专属

炼狱的 `loss_curve` 在节点 8 之后从 **0 跳到 11**（`[0,4?...]` 见下表），
再往后 19 / 21 / 23 / 38 —— 也就是「进入第 9 关之后，输一次掉掉 1/6 信标，输两次就没了」。
敌方还叠着 1.30 倍数值 + 吃满羁绊 + BOSS 的 `armor_pierce` 壁垒。

一句话：**炼狱不缺操作，缺容错**。所以给它加经济（不是给别的档减）。

⛔ 简单 / 普通 / 困难**一个字节没动** —— 那三档不缺钱，加了只会让难度塌掉。
验收里有专门的对照断言守着这件事（见 §六）。

## 二、第 1 条：关卡收入 + 利息门槛

### 2.1 关卡奖励（逐节点）

新增难度字段 `node_income_bonus`（15 项，列序 = 节点 1..15）：

| 节点 | 1~5 | 6~10 | 11~15 |
|---|---|---|---|
| 每关额外星币 | 0 | **+1** | **+2** |

- 为什么用**逐节点数组**而不是「6 关之后统一 +2」：节点 10 和 11 的敌方强度差一截，
  收入也该差一截，两者要对得上。
- 落地在 `EveRunState.node_income_bonus()`，由 `income()` 相加。
- 按 `node_index` 取：`advance()` 是**先推进再发收入**，所以「节点 6 的 +1」
  正好落在进入节点 6 的那次结算里 —— 玩家理解就是「这一关多给一颗币」。

### 2.2 利息门槛 10 → 9

新增难度字段 `interest_step`（缺省 10），炼狱填 **9**。

| 星币 | 45 | 50 | 90 |
|---|---|---|---|
| 普通/困难/简单（÷10，上限 5） | 4 | 5 | 5 |
| **炼狱（÷9，上限 5）** | **5** | **5** | **5** |

- 只降门槛、**不抬上限**：抬上限会让「攒钱」变成唯一正解（15 关的局，上限 5 已经够）。
- 实际效果：炼狱从 45 币起就吃满利息，比其它档早 5 颗币 —— 也就是一个半护卫的价格。

### 2.3 收入日志

`收入 +N（基础 5 · 利息 5 · 关卡奖励 2）`。
顺手修了个旧 bug：日志里的「基础」原来硬写常量 `BASE_INCOME`，
现在改读难度档的 `base_income`（否则哪天一档把基础调到 6，日志就和到账对不上）。

## 三、第 2 条：抽奖池

> **⚠️ 2026-10-31 晚修订（用户原话）**：
> 「错了，是一星二星全部进一个池子，然后让玩家选，二星不是单独的池子，玩家只能选一艘」
> —— 初版做成两池两许愿是错的，已按下表改为**单池单许愿**。

| 池 | 内容 | 数量 |
|---|---|---|
| **唯一**的池 | 一星：权威表 **cost ≥ 3** 全量（巡洋 12 + 战巡 8 + 战列 12）＋ 二星：巡洋（cost 3）的 **★2** 版本（4 派系 × 3，**不分定位**，后勤也在内） | **44**（32 ★1 + 12 ★2） |

- 一星、二星**混在同一个网格**里摊给玩家，卡片用 `★1/★2` 徽标区分；
- 许愿：**全池只选 1 艘**（按「船 + 星级」精确匹配 —— 同一艘巡洋会以 ★1 和 ★2
  两个身份同时在池里，只按船名匹配会有歧义）；
- 二星船不另建数值表：`star` 是 entry 字段，舰队重建时按 `STAR_MULT^(star-1)` 放大。
  ⛔ 任何「手动乘一遍数值」的写法都是第二份星级口径。
- 「cost ≥ 3」沿用旧「黑市保底」那条线，玩家已经熟悉。

## 四、第 3 条：抽奖窗口

### 4.1 窗口长什么样

`scripts/ui/panels/eve_lottery.gd`（`extends EveWindow`，与事件面板同一套皮肤）：

```
┌─ 舰船抽奖 ─────────────────────── 节点 4 · 黑市情报 ─┐
│ 抽奖池已摊开 —— 点卡片许愿（只选一艘），抽中它额外返星币 │
│ ┌─ 全池 44 艘（8 列竖滚）────────────────────────┐ │
│ │ [★1 巨鸟级][★1 狞獾级]…[★1 恶魔级]…            │ │
│ │ [★2 巨鸟级][★2 狞獾级]…（二星 12 艘排在一星后面）│ │
│ └──────────────────────────────────────────────┘ │
│ 许愿：★1 巨鸟级（点卡片许愿，再点一次取消）          │
│                    [ 抽 取 ]                    │
└─────────────────────────────────────────────────┘
```

抽完之后**同一块地方**换成结果区（池子收起），按钮文字变「完 成」：

```
│ 抽奖完成 —— 船已进备战席（满了会折成星币），拖到棋盘即可上场 │
│ 许愿回顾：★1 巨鸟级                                        │
│ 抽取结果                                                    │
│ ┌ ★2 抽到 ────────────┐                                   │
│ │ 狞獾级               │                                   │
│ │ 3 费 · 已进备战席     │                                   │
│ │ 未命中许愿            │                                   │
│ └─────────────────────┘                                   │
│                    [ 完 成 ]                                │
```

### 4.2 规则口径

| 项 | 口径 | 理由 |
|---|---|---|
| 抽几次 | **只抽 1 艘**（`LOTTERY_DRAW_TIMES = 1`） | ★ 用户 2026-10-31 定案：「玩家抽到的是两艘，这不对，得是一艘，不然奖励就太丰厚了」。奖品的定位是彩头，不是白送 3 费船 |
| 花不花钱 | **免费** | 这是事件的追加奖励，不是商店 |
| 船去哪 | 备战席；**满了折成星币**（= 该船一星价格） | 见 §5.2 |
| 许愿命中 | **全池只许愿 1 艘**，按「船 + 星级」精确匹配；命中额外返 **该船的一星价格**（`cost`） | 同一艘巡洋会以 ★1/★2 两个身份同时在池里，只按船名匹配有歧义；二星按一星计价 ⇒ 也是 3 |
| 许愿必须选吗 | 不必，空愿望照样能抽 | 奖励是彩头，不是门槛 |
| 能跳过吗 | 不能（窗无关闭按钮） | 它挡着节点推进；"跳过白给的奖励"没有意义 |

> ⚠️ **一局最多抽一次**：抽奖挂在「黑市情报」上，而事件表是 `ALLOW_REPICK = false`
> （同一条增益不能拿第二次）⇒ 三个事件节点（4 / 10 / 14）里只有一次能拿它。
> 这是**既有结构**决定的，不是本轮的额外限制。要改成"每个事件节点都能抽"，
> 就得给抽奖另立一条选项或另开一个触发点 —— 那是另一个需求。

### 4.3 流程接线（真实链路）

```
prep.on_event_chosen(&"black_market")
   → run.apply_event()            落地「免费高级刷新预约 + 本批半价」  ← 必须先做
   → hud.show_lottery(pool)       （单池 44 艘）
   → lottery_open = true          ⛔ 这里**不** advance()（否则节点推两次）
点卡片许愿 → 点「抽取」
   → hud.lottery_draw_requested → prep.on_lottery_draw
   → run.lottery_draw(wish_key, wish_star) × DRAW_TIMES(2) → hud.show_lottery_result
点「完成」
   → hud.lottery_finished → prep.on_lottery_finished → _advance_after_event()（推进节点）
```

### 4.4 AI 操作面

`ai_event_state()` 多一个 `lottery_open`；新增命令 `lottery`（抽 1 艘 + 点完成，一次走完，
可带 `wish_key`/`wish_star` 参与许愿）。
⛔ 不给这个字段 / 命令的话，AI 会看到「事件已选、面板全关、节点不动」然后无限重试 ——
和 2026-10-05 打捞那个死循环是同一类病。

## 五、踩到的坑与决策

### 5.1 「黑市情报」不是新增的第 5 条选项

选项表是 4 选 3 的取舍结构。加第 5 条会把整个事件节奏重排（用户没要求），
而且用户原话就是「抽船 3 费以上舰船**那个事件**」—— 他指的就是黑市情报。
所以做的是「挂在同一条选项上的追加环节」，由 `opens_lottery` 声明 + 难度档 `event_lottery` 二次把关。

### 5.2 备战席满了为什么不塞进货架

货架每一格都跟「玩家花不花钱 / 刷新会不会刷掉」绑定。奖品插进去会立刻长出
「这格是不是我买的」「锁店会不会把它锁住」一整套歧义。
备战席满本身很罕见（8 格），**折成星币**比制造歧义干净，而且有明确日志：

```
抽奖：狂暴级 ★1 无处安放（备战席已满）⇒ 折成 5 ◆
```

### 5.3 结果卡第一版是两块黑砖

第一版给结果卡 `SIZE_EXPAND_FILL`，结果它撑满 400px 高、字全挤在左上角，
截图里像两个空面板。改成 `SHRINK_BEGIN` + 固定 108 高。

### 5.4 许愿选中态第一版「看不见」

第一版只把边框 1px→2px、alpha 0.34→1.0。深底 + 细边，缩图后完全糊掉。
现在三件事一起做：**金边 2px + 偏金的底 + 名字转金色**。

### 5.5 「完成」按钮一度跑到了结果卡上方

VBox 的顺序决定了谁贴底。第一版是 `… → 抽取按钮 → 结果区`，
抽完之后按钮就在结果**上方**了。改成 `… → 结果区 → 按钮`，
按钮永远在最底 —— 抽取前后位置不跳，手指不用重新找。

## 六、验收

| 套件 | 结果 |
|---|---|
| `verify_run` | **1030 项通过 · 0 项失败**（初版 +37，合并池修订后重写为 34+3 条） |
| `verify_ui_scale` | **263 项通过 · 0 项失败**（桌面档位表 11 项 → 12 项：多了抽奖窗） |
| `tools/run_verifies.sh` | 22 套全过（详见运行日志） |

本轮新增断言：

- 难度字段：炼狱有 `event_lottery` / `interest_step=9` / 15 项奖励曲线；**其余三档一个都没有**
- 利息：炼狱 45 币 → 5，普通 45 币 → 4
- 关卡奖励：节点 5 = 0 / 6 = 1 / 11 = 2；普通档节点 11 = 0
- 收入总额：`基础 5 + 利息 5 + 关卡 2 = 12`（三处一起对，防止只加在某一路径）
- 池子（修订后单池 44 艘）：32 艘 ★1 全 `cost≥3`/`star==1`；12 艘 ★2 全 `cost==3`/`star==2`/覆盖 4 族/**含后勤**；一星二星在**同一个网格**里
- 许愿（修订后单选）：全池只选 1 艘，按「船 + 星级」匹配 —— 同一艘巡洋的 ★1/★2 视为两张不同的许愿卡
- 开窗条件：炼狱 + 黑市情报 = 是；普通 + 黑市情报 = 否；炼狱 + 其它选项 = 否
- 抽取：同种子两局 ⇒ 同一条随机序列 ⇒ 许愿同一艘必命中，且返币真的到账（`coin` 对账）
- 免费：没许愿时星币分文不动
- 二星：抽到的是 ★2，按一星计价 = 3
- 修订（合并池）：许愿 ★2 巨鸟级、抽中 ★1 巨鸟级 ⇒ **不算命中**（星级也要对上）
- 场景：抽奖窗已建；**非炼狱局不会误弹**；窗矩形在 1920×1080 内
