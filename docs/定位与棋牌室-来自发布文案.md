# 从发布文案看产品定位 —— 以及它和棋牌室的关系

> 2026-10-06 · 依据：用户《EVE自走棋新版本》发布视频文案
> 用途：**以后做任何"要不要做 / 怎么做"的决定，先回来对一遍这份定位。**
> 尤其：棋牌室的美术到底该怎么做、军团礼装从哪儿切进去。

## 一、文案里的六条产品哲学（原文是关键，别转述）

| # | 原文 | 我的解读 |
|---|---|---|
| 1 | 「EVE 自走棋**那就既得是 EVE 又是自走棋才对**。所以在整个色系和 UI 风格上我就没做特别大的更改，尽量像 EVE 的 UI 一些。总体上**不是那种繁复绚丽的**」 | ★ 这是**风格宪法**：冷色、克制、信息优先。任何新界面都得先过这一条 |
| 2 | 「这次没做美术和音乐音效，**主要还是想要先完善核心玩法，就怕最后连个自走棋都不是了**」 | 优先级 = **玩法 > 表现**。但注意：这是"先"，不是"不做"（下一条） |
| 3 | 「**现在的表现力还是很差**，也有很多需要提升的地方」 | ★ 用户**自己承认表现力是已知短板** ⇒ 做装饰不是跑题，是在补他明确点出的坑 |
| 4 | 「打捞舰船…**是我们这个 EVE 自走棋区别于其他自走棋最大的不同**…相信这会形成新的思考链路并产生新的博弈」 | 核心差异化 = **舰船会被击毁 + 可打捞**。任何新功能都不该稀释它 |

| 6 | 「这个项目也会**开源到 github 上**，避免闭门造车」 | 代码要经得起外人读 ⇒ 注释即文档、单一真相源、别留神秘实现 |

## 二、棋牌室是怎么来的（不是冲动，是外部需求）

> 用户原话（这次）：**「我做斗地主的想法是因为我发了视频，观众给到的反馈才做的，原来他们是想要这个」**
> 观众原话：**「为什么你们都那么爱玩自走棋…我们只是想要舰长室，小游戏来个斗地主 麻将」**

三个可直接用的结论：

1. **棋牌室是"外部需求"，不是自娱** ⇒ 它的验收标准是**群友玩不玩**，不是"我觉得好不好"。
2. **观众要的是「舰长室」** —— 不是"一个牌桌界面"。★ 所以棋牌室的视觉主题就是
   **舰长室（太空舱内 + 舷窗外）**，这个方向有出处、不是我编的。
3. 场景是**「蹲站的时候有玩的」** ⇒ 棋牌室是**等待 / 社交场景**，不是"沉浸打一局"。
   ⇒ 它跟自走棋抢时间的风险其实很低；它服务的是**留存与军团内部社交**。

---

## 三、★★ 最关键的推论：棋牌室的装饰 = 军团礼装的第一块试验田

把文案第 5 条和棋牌室对起来看：

```
文案承诺的「军团独有的外观」三件套
├── 主界面     ← 主菜单 / 棋牌室入口（未做）
├── 舰船皮肤   ← 自走棋侧（未做）
└── 棋盘       ← ★★ 棋牌室的「背景 + 牌桌」就是这一项的第一次落地
```

**为什么棋牌室是最合适的起点**：

| 理由 | 说明 |
|---|---|
| 模块独立 | 棋牌室与自走棋**零耦合**（独立场景、独立脚本），礼装做砸了不影响主线 |
| 视觉需求明确 | 只有"背景 + 牌桌"两件东西 —— 好定义、好验收、好替换 |
| 场景契合 | 「蹲站社交」正是军团成员聚在一起的地方 ⇒ 军团外观在这里**最容易被看见** |
| 代价最低 | 零新素材也能做出效果（本轮就是）⇒ 验证成本低 |

⇒ **由此定下一条工程纪律**：
> 棋牌室的一切美术，**一律按「可整块替换的礼装」写**，⛔ 不写死。
> 换礼装 = 换一段常量，**不动绘制函数**。

本轮已经照这条做了：`ddz_table.gd` 里圈了一块 **「棋牌室礼装」常量区**
（背景贴图 + 舱壁/桌面配色 + 装饰语言全在里面），换它就能换整套外观。

## 四、本轮落地：棋牌室 = 舰长室

### 做了什么

| 项 | 做法 | 依据 |
|---|---|---|
| **背景** | **整屏深空**（星云 + 星点）+ **四周舱壁结构框**（左右立柱带刻度、顶部结构带、屏幕安全框 L 形角标） | 概念来自观众要的「舰长室」；风格来自文案第 1 条（EVE 冷色、不繁复） |
| **背景素材** | `caldari-c02-nebula-4096`，**1:1 取样**（⛔ 不缩放，该图没开 mipmap，缩放必出锯齿） | 做了 5 张对照表之后挑的：均值亮度 33/255 最像深空 |
| **取样偏移** | 把星云那团**亮核推到右下角**（牌桌之外的可见区） | 放正中会被牌桌整个盖掉 —— 出图看出来的 |
| **牌桌** | 细网格 + 中央战术刻度环 + **四角 L 形结构标记** + 上沿高光/下沿内影（做出厚度） | EVE 的 UI 语言就是「细线网格 + 刻度 + 角标」，而且天生低对比 ⇒ 同时满足"像 EVE"与"不抢注意力" |
| **桌面亮度** | 比深空**亮一档** | 要能分辨；但仍远低于卡牌 ⇒ 玩家视线在牌上 |

### 走过的弯路（留着，别再走）

1. **第一版是「墙上开一扇舷窗」** —— 结果牌桌把窗子挡掉大半，
   左右只剩两块浅灰斑，**看着像 bug 不像窗**。⇒ 改成"整屏就是窗外，舱壁只做边框"。
2. **背景素材不能随便挑**：c07-nebula(117) / c07-menu(126) 太亮 ⇒ 压暗后是一团灰雾；
   amarr(62) 偏暖金、gallente(31) 发绿糊。⇒ 必须**先做对照表再挑**（`_shots/bg_candidates.png`）。
3. **星点素材铺上去几乎看不见**（本身是细小亮点）⇒ 需要 `modulate > 1` 提亮。

## 五、接下来（按文案定位排的优先级）

| 优先级 | 事项 | 为什么是这个顺序 |
|---|---|---|
| **高** | **军团礼装的最小可玩形态**：让「换一套礼装」真的能生效（哪怕只有两套内置配色） | 把文案里的承诺变成**看得见的东西**；也是棋牌室装饰的上位概念 |
| 高 | 棋牌室的**主界面**外观（进棋牌室那一刻的氛围，与任务关卡区分开） | 军团礼装三件套里的「主界面」 |

## 六、一句话记住

> **棋牌室不是"顺手加的小游戏"，它是「军团礼装」这条对外承诺的第一块地。
> 所以它的一切美术都要做成"能整块换掉"的形状 —— 这是工程要求，不是洁癖。**
