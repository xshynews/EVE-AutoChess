# 多人对战架构：AI 对战 · 人机 · 联机

> 2026-10-27 ｜ 目标：把「AI 和人对战」直接做成**多人对战架构**，
> 以后接真人联机只是把「本地玩家」换成「网络玩家」，不动核心。

## 一、云顶之弈的多人结构（外部调研）

来源：en.wikipedia.org/wiki/Teamfight_Tactics

```
整局 8 人，最后存活者胜
├─ 阶段 1：3 回合，全是 PvE（小兵）
├─ 阶段 2：7 回合
├─ 阶段 3：7 回合
└─ ...

每个阶段内（7 回合）：
  回合 1~3   随机匹配另一名玩家对战（PvP）
  回合 4     选秀 Carousel（第 3 回合后触发）
  回合 5~6   随机匹配另一名玩家对战（PvP）
  回合 7     打电脑敌人（PvE / BOSS）

掉血规则：输的一方的掉血量 = 对方存活单位数 x 回合数权重
   ⇒ 后期输一次远比前期疼（这是「速死 vs 运营」的核心张力）

选秀细节：免费、共享轮盘、单位自带随机装备
  选取顺序 = 按当前血量从低到高（血量低的先选，追赶机制）
  两人一组同时选
```

## 二、和 EVE 自走棋的现状对照

| 维度 | 云顶 | EVE 自走棋（现在） | 迁移成本 |
| --- | --- | --- | --- |
| 对局单位 | 8 名玩家 | **1 名玩家** + 固定敌方编组 | 要抽一层「房间」 |
| 回合 | 阶段 x 回合 | **15 个节点**，线性 | 节点表可直接当回合表用 |
| 对手 | 其它玩家的舰队 | `EveNodeTable` 写死的编组 | PvP 回合换成读对手段 |
| 血量 | 100，按存活单位掉 | **信标 100**，按节点固定扣 | 已等价，改掉法即可 |
| 战斗 | 已支持 2 队对战 | `EveBattleSimulator` **本来就是 2 队** | 零成本，直接能 PvP |
| 选秀 | 共享轮盘 | 事件四选一（节点 4/10/14） | 事件表就是选秀表 |
| 经济 | 每回合发钱+利息 | 已有利息 + 节点收入 | 已等价 |

**关键发现**：`EveBattleSimulator` 吃的是「红方舰队 / 蓝方舰队」，
**根本不关心蓝方是人、AI 还是写死的编组**。所以 PvP 是零成本的——
把「敌方编组」这个数据源从 `EveNodeTable` 换成「另一个玩家的舰队」就行。

## 三、架构：三层，中间层是新的

```
┌─────────────────────────────────────────────┐
│  EveMatchState          【新】房间 / 对局      │
│  · players: Array[EveMatchPlayer]            │
│  · stage / round / round_kind                │
│  · pairings: 本回合谁打谁                     │
│  · 掉血 / 淘汰 / 胜负判定                     │
├─────────────────────────────────────────────┤
│  EveMatchPlayer         【新】一个玩家         │
│  · hp（= 现在的信标）                        │
│  · is_ai: bool                               │
│  · run: EveRunState   【复用】舰队/金币/等级   │
│  · brain: 决策器（AI 玩家才有）               │
├─────────────────────────────────────────────┤
│  EveRunState            【复用，几乎不动】     │
│  舰队 / 备战席 / 星币 / 等级 / 羁绊统计        │
└─────────────────────────────────────────────┘
```

### 为什么这样分

1. **`EveRunState` 一行不改**——它是「一个玩家的全部私有状态」，
   单机已经在用，复用即零风险。
2. **`EveMatchPlayer` 只做两件事**：持有 hp、标记是不是 AI。
   它是「房间里的一名参与者」，不是「一局游戏」。
3. **`EveMatchState` 是唯一的新概念**：回合推进、配对、掉血、淘汰。
   以后接网络，只需要把「所有玩家同时进入准备阶段」这一步
   从「本地同时」换成「等网络齐」——**其它逻辑一行不改**。

## 四、回合推进（照着云顶，但适配 15 节点）

现在 15 个节点是线性的。改成阶段 x 回合：

```
阶段 1（3 回合，对应节点 1-3）   全 PvE      —— 新手期，和人打太劝退
阶段 2（7 回合，对应节点 4-10）  回合 4 = 选秀（= 现在的事件节点）
阶段 3（5 回合，对应节点 11-15） 最后一回合 = BOSS

每回合的固定顺序：
  ① 准备阶段（所有玩家同时；AI 玩家由 brain 驱动）
  ② 配对：PvP 回合随机抽一名**还活着**的对手（云顶同口径）
  ③ 逐个跑 EveBattleSimulator
  ④ 掉血：输方 hp -= 对方存活单位数 x 回合权重
  ⑤ 淘汰 hp <= 0 的玩家
  ⑥ 只剩 1 人 ⇒ 对局结束
```

### 和现在的关键差异

| | 现在（单机） | 多人 |
| --- | --- | --- |
| 输的代价 | 按 `loss_curve[node]` 固定扣 | 按**对方存活单位数 x 回合权重** |
| 赢了得到什么 | 什么都没有 | **不掉血就是收益**（相对概念） |
| 对手强度 | 写死的 | **其他玩家也是成长的** ⇒ 要卷 |
| 追击机制 | 无 | 选秀按血量低的先选 |

## 五、AI 玩家 = 一名普通玩家 + 一个 brain

AI 玩家的 `run` 和人类玩家的 `run` **完全同构**，唯一区别是
准备阶段谁来操作。所以 brain 只需要实现一个接口：

```
class_name EveAiBrain
func take_prep_turn(player: EveMatchPlayer) -> void:
    # 内部就是 ai_mouse_bot 那套决策（定体系 / 凑羁绊 / 星币纪律 / 布阵）
    # ⚠️ 关键：brain 只做「决策」，不做「输入」。
    #    人类玩家用鼠标操作，AI 玩家直接改 run 状态 —— 两者终点一致。
```

**这一点很重要**：AI 玩家不需要模拟鼠标。鼠标是给「演示给人看」用的，
不是游戏逻辑的一部分。这样 brain 可以跑得很快（不需要等动画），
而人类玩家的操作节奏完全不受影响。

## 六、探针的已知限制（重要，别踩）

tools/probe_match_rounds.gd 目前跑不起来，原因不在代码：

```
godot --headless --script tools/probe_match_rounds.gd
```

`--script` 模式（SceneTree）**不注册 class_name 全局类**，
所以连 EveRunState 自己都解析不了 EveShip / EveCampaignTiers，
报一堆 "Identifier not declared"。同理，把新类临时挂成 autoload 也不行
（autoload 加载早于全局类缓存建立）。

**正确的验证方式**：从一个**场景**里引用它们（场景加载会建全局类缓存）。
下一步把探针改成 .tscn + 脚本，或在战斗场景里挂调试入口。
