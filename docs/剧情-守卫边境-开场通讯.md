## 1.6 头像资产（**只裁切，不放大**）

> ⚠️ 2026-09-30 晚改定。第一版我按"脸宽归一"把队长放大 2.10×、斥候 1.55×，
> **用户反馈看着很别扭** ⇒ 撤回。现在只做「裁成同一尺寸」，不做任何头脸放大。

`assets/portraits/` —— 三张统一为 **477×455**：

| 文件 | 原图 | 裁切 | 净缩放 |
|---|---|---|---|
| `头像_队长.png` | 468×457 | 裁成 468×446（去上下） | **1.019×** |

## 1.7 生成脚本

| 脚本 | 作用 |
|---|---|
| `C://godot//_export//_intro_dialogue.py` | 生成对话 UI 帧序列（**带 alpha**）+ 静帧预览 |
| `C://godot//_export//_intro_encode.py` | 把帧序列编码成 qtrle / ProRes4444 / VP9-alpha + 叠底预览 MP4 |

**可调参数集中在 `_intro_dialogue.py` 顶部**：`CPS`（逐字速度）· `HOLD`（句末停顿）·
`ACT_GAP`（换幕停顿）· `BAND_Y/BAND_A`（半透明带位置与浓度）· `PORT_X/PORT_Y`（头像位置）

## 3. 第 ② 步 · 信标展开动画

素材与动作规格已就绪（见 `C:\godot\_export\_cyno_deploy\移动式诱导信标_资源清单.md`）：

| 项 | 值 |
|---|---|
| 模型 | `pcd01_t1`，46.6 × 103.3 × 46.6 m（**模型 +Y 朝下，需 R_x(180°) 立正**） |
| 四片桨叶 | 根部 r 28.4 / 切向宽 11.07 m；梢部 r 70.8 / 切向宽 4.68 m；展开仰角 **−25.3°** |
| 转轴 | 根部**切向轴**（单自由度） |
| 动作 | 收起 −90°（竖直贴塔身）→ 展开 −25.3°，摆动 **64.7°**，带 **7% 过冲** |
| 时序 | 0~0.72 展叶 · 0.25~0.85 环放大 · 0.45~1.0 顶端等离子柱点燃 |
| 总长 | **≈ 1.4 秒** |

**镜头**：对局俯视视角 → 拉近信标特写 → 展开完 → 退回俯视（总长约 2.5~3 秒）。
镜头轨道要**可调**（工程相机 `EveOrbitCamera` 有现成的 `DEFAULT_ZOOM` 联动不变量，

⚠️ 信标必须**真的出现在对局场景里**（玩家之后要守它），不能只在动画里露个脸就消失。

## 4. 第 ③④ 步 · 任务方框

一个 `EveWindow`（直角 · 1px 边框 · `rgba(14,18,21,.84)` 底），**上半 + 下半一次看完**，
底部**一个**按钮「关闭 ▸ 开始」。

### 上半 · 本局任务

```
        本局任务
   ──────────◆──────────
   守卫移动式诱导
   共计 15 回合，包含事件回合
   信标归零即撤离
```

- 标题「守卫移动式诱导」用信标蓝
- ⚠️ **术语**：对话里说「移动诱导」是口语，没问题；但**方框/UI 必须写全名「移动式诱导信标」**
  （与资产、与 `EveCampaignTiers` 的口径一致）
- ⚠️ 我加了一行「**信标归零即撤离**」：这是现有机制（`advance()` 里 `beacon <= 0` → 结局），
  但**任务框里不说，玩家就不知道会输**

### 下半 · 星币（◆）

两栏，左「获取」右「消耗」。**数字全部从代码取，不许在 UI 里手写**
（真源：`EveRunState` 的常量 + `income()` / `sell_value()` / `salvage_cost()`）。

```
        星币  ◆

  ── 获取 ──────────────────   ── 消耗 ──────────────────
  起始            5           买船        = 船的吨位档 1~5
  每回合基础      5           刷新加速列表            2
  利息  存 10 得 1，上限 5     加速等级  经验 +4        4
  出售返还  吨位 × 3^(星−1)    超频（满级后）商店品质 +1  16
  事件 · 补给仓  立即 +12      打捞     ⌈吨位 × 0.5⌉ 起
             之后每回合 +2
```

细节注释（放在小字里，或做成 hover 提示）：

- **利息**：每存 10 ◆ 得 1，**最多 5**（即存满 50 ◆ 吃满）
- **出售返还**：★1 → 吨位 ×1 · ★2 → ×3 · ★3 → **×9**（`cost × 3^(星−1)`）
- **打捞**：当场扣钱，**下个节点才到账**，且会**顶掉 1 个商店货位**
- **加速等级**：每完成一个节点还会自动 +2 经验（不花钱）；花钱是额外加速
- **超频**：只有**满级之后**才会出现这个选项（商店品质再 +1 档，最高 8 档）
- 所有消费**只能在准备阶段**（战斗/结算阶段按钮全灰）

> 顺带：台词里那句「守好信标我给你奖金」正好把上面这一屏**变成剧情内的东西** ——
> 玩家领的钱是队长的战功奖金。建议标题就写「**战功奖金 · 星币**」，比「星币说明」有味道。

### 第 ⑤ 步 · 关闭

点「关闭 ▸ 开始」→ 关方框 → 进节点 1 准备阶段 → 节点 1 进场词横幅照常弹
（「前方发现两艘散兵级。信号识别为游荡掠夺者。」）。

⛔ 不要在这里再弹一次"敌人是谁"，跟进场词打脸。

## 1.8 ★ 「背景视频和对话内容对不上」怎么办

这是目前唯一的真风险，我按「从根上消掉 → 兜底」排三层：

### 方案 ①（推荐）背景不承担叙事，只做气氛 —— 从根上消掉问题

整段 20 秒用**一个连续镜头**（缓慢推镜 / 平移），**不切**。
那就不存在"对不上"——**无论台词怎么改，背景都不用动**。

代价：少了"星门 / 哨站"的画面切换。
但这段的功能是**铺垫 + 教学**，不是奇观；一个稳定缓慢的太空镜头的"静"，
反而衬托后面信标展开那一刻的"动"。

### 方案 ② 要切就切在「幕」上，且时间码由我参数化重排

四幕只有 **3 个切换点**。而且幕的起止时间不是写死的，是
`_intro_dialogue.py` 里 `CPS / HOLD / ACT_GAP` 三个参数算出来的
⇒ **我改参数就能重新对齐你的镜头，UI 一行都不用重做**。

### 方案 ③ 最稳：让台词去迁就画面（不是反过来）

**先定背景的 4 段起止时间**（例如 `0 / 5 / 10 / 15` 秒切），
我再按这 4 个时间点去分配台词与该停多久。
理由：**画面的切换是刚性的，玩家读字的速度是弹性的**。
让弹性的一侧去适应刚性的一侧，风险最小。

### 所以正确的交接顺序

```
1. 我先给透明层（✅ 已完成）+ 参数化时间轴脚本
2. 你剪背景、定下 4 段的起止秒数
3. 你把时间点发我 → 我改参数重出透明层（几分钟）
4. 你合成
```

⚠️ **不要反过来**（先按我的时间码剪好背景，再回来改台词）——
那样每改一个字都可能要重剪。

### 顺带一个能省事的决定：成品是「烘成一段视频」还是「引擎里实时合成」

| | 路径 A · 烘成一段成品视频 | 路径 B · 引擎内实时合成 |
|---|---|---|
| 做法 | 你的背景视频 + 我的透明层 → 合成一段 21 秒 mp4 → 游戏里 `VideoStreamPlayer` 播 | 视频当纹理铺底，UI 用 `Label` 实时画 |
| 优点 | **UI 完全不用在引擎里做，最省**；画质稳定 | 可交互（跳过 / 点任意处补全）；可改文案；自适应分辨率 |
| 缺点 | 文字是死的；跳过要另做；改文案得重出 | 要做引擎工作 |

**建议：先走 A**（最快看到成品，也方便你反复调），**文案定稿后再考虑 B**。
两条路的上游素材是**同一套**（透明层 + 时间轴），不冲突。
