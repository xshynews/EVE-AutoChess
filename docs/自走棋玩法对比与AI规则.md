# 自走棋玩法对比 · 鼠标操作规则 · AI 决策规则

> 2026-10-26 ｜ 目的：让 AI 真的会玩 EVE 自走棋，而且只用鼠标。

## 一、自走棋这个品类的骨架（外部设计资料）

来源：Auto-Battler Design Codex（hayao.dev）、TFT 新手攻略、云顶之弈运营文章。

### 1. 四条支柱

| 支柱 | 含义 | 对 AI 的含义 |
| --- | --- | --- |
| **准备期才是游戏**，战斗只是揭晓 | 所有能动性都在商店和棋盘上 | 决策要花在买/刷/摆，战斗只能看 |
| **经济是脊椎** | 金币 / 利息 / 刷新 vs 存钱 / 等级 vs 战力 | 每一枚星币的机会成本都要算 |
| **羁绊强于面板** | 战力来自组合（羁绊、档位、站位） | 别只看单卡强度，要凑档 |
| **池子是约束** | 共享卡池，抢卡是有意义的操作 | 别跟自己的体系抢卡 |

### 2. 标准循环

```
买 / 卖 / 刷新 / 重摆  →  回合开打（自动）  →  评分  →  调整  →  再来
```

### 3. 经济模型（TFT 口径，与本工程一致）

- **利息**：每 10 金 +1，上限 5。⇒ 40 金是「利滚利」的甜蜜点。
- **刷新**：固定花费，属于「用钱换方差」。
- **买经验**：用钱换人口 + 更好的商店概率。
- **节奏**：前期存钱、中期（约 4 级）开始花钱提战力、后期梭哈。

### 4. 站位必须**可证明地**影响结果

设计法典原话：「同样的单位摆得差就该输给摆得好 —— 这才是『棋盘是真决策』的证明」。

## 二、EVE 自走棋的对照（本工程实测口径）

### 1. 一致的部分（可以直接套用通用打法）

| 通用机制 | EVE 自走棋实现 |
| --- | --- |
| 准备期 → 自动战斗 → 结算 | ✅ 同样是 PREP / BATTLE / RESOLVE |
| 利息 | ✅ min(⌊gold/10⌋, 5) |
| 刷新花费 | ✅ 2 ◆ |
| 买经验 | ✅ 4 ◆ → 4 点 |
| 等级 → 商店概率 | ✅ 8 档表，Lv6 出 5 费 |
| 上场上限 = 等级+2 | ✅ LEVEL_CAP |
| 羁绊（trait） | ✅ 势力 2/4、武器 3/6、防御 3/6 |
| 共享卡池 | ⚠️ 每费一个池，**但电脑对手不抢卡**（单人爬塔） |

### 2. 不一样的部分（**不能照搬 TFT 思路**）

| 维度 | TFT | EVE 自走棋 |
| --- | --- | --- |
| 对局结构 | 8 人混战，互相消耗 | **单人爬塔，15 个节点**，每节点一个敌方编组 |
| 输的代价 | 掉血，可复活 | **信标 100**，掉光即撤离（一次性） |
| 站位 | 关键（前排/后排/切后排） | **几乎不重要**：11×11 只是布阵辅助，战斗是连续机动 |
| 羁绊上限 | 3~9 档 | **只有 2 档**（一档/二档） |
| 特殊资源 | 海克斯 | **事件四选一**（节点 4/10/14） |
| 补充手段 | 选秀 | **打捞残骸**（半价买敌方高费船） |
| 敌方 | 其它玩家 | **固定编组**，可背板 |

### 3. 由此推出的三条 EVE 专属认知

1. **站位不用研究，凑羁绊才是全部**。因为战斗是 3D 连续机动 + compute_deploy_z() 自动定接敌距离，
   玩家摆哪一格几乎不改变结果。⇒ AI 只要「填满格子」即可，不必优化阵型。
2. **敌方是背板的**。15 个节点的编组固定，所以「这一关是什么武器/什么防御」可以提前知道
   ⇒ 理论上 AI 可以针对性凑克制体系（导弹破甲墙、盾抗扛导弹）。
3. **打捞是唯一的「升维」通道**。商店受等级限制摇不出高费船，而残骸里有敌方的高费船（半价）。
   ⇒ 每节点有残骸就要捡。

## 三、鼠标操作规则（本工程实测得出，可直接复用）

### 1. 坐标：warp_mouse 与 get_global_rect **不是同一个坐标系**

实测：

```
Control.get_global_rect()  →  视口坐标
Input.warp_mouse()         →  DisplayServer 窗口坐标
本机窗口 2064x1191 时，偏移 = (+60, 0)
```

**规则**：
- 进场先调 calibrate_mouse 量一次偏移并缓存；
- 点控件一律用 ui_click_path（游戏内部过偏移量）；
- 绝不手写「矩形中心」直接点。

### 2. 点击规则

| 目标 | 用什么 | 为什么 |
| --- | --- | --- |
| HUD 按钮 | ui_click "文字" | 按名字找，自带校准 |
| 商店卡 | ui_click_path <path> | 卡是 PanelContainer，不是 Button |
| 棋盘格 | **不能直接点** | 格子是 3D 投影，且棋盘只在拖拽时入画 |

### 3. 布阵 = **分阶段拖拽**（唯一可行）

```
① mouse_down 备战席格        → 棋盘入画（_begin_drag_visual → show_board_for_deploy）
② 等 0.9~1.4s                → 取景平滑收敛，格子坐标才有意义
③ cell_point(row, col)       → 用游戏自己的 screen_to_cell() 反查真实屏幕位置
④ mouse_move 分 5~8 段挪过去  → 光标走得见，且触发 update_drag 的落点判定
⑤ mouse_up                   → 松手生效
```

⛔ 一口气 mouse_drag 必错：按下那一刻棋盘还没入画，格子坐标是飞的（实测飞出屏幕几万像素）。

### 4. 其它硬规则

- **光标必须真的动**（warp_mouse），观众才看得见；
- **每步之间留白**（演示模式 2.6s/步），否则一屏几十行没人跟得上；
- **失败必须出声**：每个动作回执都要检查 ok，不能静默重试。

## 四、AI 决策规则（本工程定制）

### 1. 经济

```
目标：每节点结束时把星币花到 < 10（利息台阶），但保留 >= 2 以便刷新
买入优先级：能补羁绊档位 > 高费 > 便宜
买经验：星币 >= 12 且 等级 < 6 时买一档
刷新：只在「买不起任何卡且星币 > 10」时刷
```

### 2. 羁绊（这是核心）

每艘船在**每组里只算 1 点**，取它命中的第一个标签：

- 势力：艾玛 / 加达里 / 盖伦特 / 米玛塔尔（2 艘一档，4 艘二档）
- 武器：激光炮 / 混合炮 / 射弹炮 / 导弹（3 艘一档，6 艘二档）
- 防御：甲抗 / 盾抗（3 艘一档，6 艘二档）

**决策**：
1. 统计当前 field + bench 的三组计数；
2. 商店里如果有能**把某组从 n 推到下一档**的卡，优先级最高；
3. 其次买同组已最多的那个标签（滚雪球）；
4. 一档最容易到：**武器 3 艘** 或 **防御 3 艘**。

### 3. 布阵

- 上场数 = min(等级+2, 备战席数量)；
- 位置：从第 7 行第 0 列开始顺序填；
- **绝不空手上阵**（0 艘 = 判负 + 扣信标）。

### 4. 战斗

- 什么都不用做（不能操作）；
- 打完看结果，进结算页点「继续」。

### 5. 结算 / 打捞

- 有残骸且买得起就打捞（半价换高费船）；
- 还有残骸没捞完会弹「放弃打捞」确认框 ⇒ 先应答它，否则卡死。

### 6. 事件节点（4 / 10 / 14）

四选一偏好：**星币 > 经验 > 信标上限 > 免费刷新**（前期钱最值钱）。
需要选船的（武器调校 / 结构加固）优先给**费用最高**的那艘。
## 五、实测踩到的四个硬坑（都会「静默失败」）

### 1. ⛔ `Input.parse_input_event` **不驱动 Button 按下**

这是最贵的一个坑：

```
Input.parse_input_event(按下/抬起)  →  hover 会变，但 Button 的 pressed 不触发
Viewport.push_input(ev, true)      →  正常触发
```

症状极具误导性：`.get_global_rect()` 对、`gui_get_hovered_control()` 也报对了、
`pressed` 事件也发了 —— **就是什么都不发生**。
我第一次误判成「坐标偏移」，绕了很久。

⇒ **所有合成鼠标事件一律走 `get_viewport().push_input(ev, true)`**。

### 2. `warp_mouse` 与 `get_global_rect` 不是同一坐标系

`Input.warp_mouse()` 走 DisplayServer（窗口坐标），`get_global_rect()` 是视口坐标。
本机实测偏移 (+60, 0) —— 正好等于 `LAYOUT.origin_of()` 的居中量。

⇒ 进场 `calibrate_mouse` 量一次，之后所有点击走 `ui_click_path`。

### 3. 同名按钮会点错

暂停遮罩里也有一个「继续」，`继续 · 下一节点` 的模糊匹配会撞上它（而且它是隐藏的）。

⇒ 选按钮必须过滤 `is_visible_in_tree()` + `mouse_filter == STOP`。

### 4. 棋盘只在拖拽中入画

`cell_point` 在 PREP 阶段返回的是飞出屏幕的坐标（棋盘还没 `show_board_for_deploy`）。
必须：按下 → 等 0.9~1.4s → 再求格子位置 → 移动 → 松手。

## 六、实测战绩（2026-10-26 首次全鼠标跑通）

- 从主菜单点进「任务关卡 / 简单」，自动跳过片头；
- 节点 1 → 2 → 3 正常推进；
- 每节点：点商店卡买 3 艘 → 拖拽上场 → 点开战；
- 结算页自动打捞 / 处理「放弃打捞」确认框；
- 事件节点用矩形点击选增益；
- **羁绊真的凑出来了**：某局场上 `艾玛 2`（装甲 +20%）+ `甲抗 3`（结构 +150）。

剩余小问题：
- 战斗期间「开战」按钮文案变成「交战中」，机器人会刷几次「找不到」——无害；
- 事件节点的选项顺序与 `event_cards` 下标需要一一对应（已按 index 匹配）。
## 七、点击精度与「误点设置」的根治（2026-10-26 补）

用户反馈：点「开战」老是点到旁边的「≡」（设置）。

### 根因

顶条上「✦ 开战」和「≡」**紧邻**（开战 [1252..1316] · 设置 [1324..1350]，只差 8px 间隔）。
偏移算错 60px 就从开战跳到设置。而设置窗一旦打开，会吃掉后面**所有**点击，
看起来就是「AI 卡住了」。

### 根治（三步）

```
① 点完必须验证：phase 没变成 BATTLE 且 settings_open 变真 ⇒ 判定为点错
② 自动用鼠标点设置窗头部的 CloseBtn 关掉它（20x18，EveWindow 统一构件）
③ 按候选偏移序列重试点「开战」：0 / +60 / +120 / +30 / +90 / ±18y
   每轮都重新验证 phase，直到真的开打
```

另外：选按钮一律过滤 `is_visible_in_tree()` + `mouse_filter == STOP`，
避免撞上暂停遮罩里同名的隐藏按钮。

## 八、玩法自动迭代（提高胜率）

机器人现在支持多轮扫荡并自己汇总：

```
node tools/ai_mouse_bot.mjs --rounds 5 --difficulty hard --watch
```

跑完打印：

```
runs 5 · cleared 2 · clear rate 40.0%
  - hard -> CLEARED · node 15/15 · beacon 79 · 121s
  - hard -> EVACUATED · node 11/15 · beacon 0 · 41s
```

### 策略三层（按优先级）

**① 羁绊优先**（这个品类的核心）

```
打分 = 能上档(+100) > 同组已多数 x 3 > 费用 x 2
买完立刻更新计数 —— 后面几张卡的打分才准
备舱 8 格上限：满了就不买（买了也进不来，纯浪费）
```

**② 星币纪律**

```
· 保留 2 ◆ 刷新费（利息台阶是 10，低于 10 不亏）
· 星币 >= 12 且 等级 < 6 → 买一档经验（多一个上场位 + 概率上移）
· 残骸半价必捡：换一艘当前档位摇不出的高费船
```

**③ 布阵与止损**

```
· 上场数 = min(等级+2, 备舱数)，绝不空手上阵（0 艘 = 判负还扣信标）
· 顺序填第 7 行起（站位在这个游戏里几乎不影响结果，见第二节）
```

## 九、当前已知边界

- 战斗中「开战」按钮文案变「交战中」/「结算中…」，机器人会报几次「找不到」——无害，
  它靠 phase 判断而不是按钮状态；
- 事件节点按 `event_cards` 的下标点击，需要 options 与卡一一对应（已按 index 匹配）；
- 一局真实时长 1~3 分钟（战斗要真跑完），多轮扫荡请用 `--delay` 调慢演示或去掉 `--watch` 快跑。
