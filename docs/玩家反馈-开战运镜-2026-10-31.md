# 开战运镜（2 秒三拍）—— 表现层

> 玩家原话：「两军对垒，是不是可以加个 环绕的主将相互靠近的机制?」
> 用户拍板（第一轮）：「主要还是 B 方案，但需要加个限时机制，开战 30 秒后还是没结果，主力舰就接近吧」
> 用户拍板（第二轮）：「行，按 2 走」—— 即本文这一项：**表现层加 2 秒开战运镜**（不进 sim，TTK 不变）

---

## 一、为什么不是继续改数值

B 方案（分层站位 + 30 秒主力压上）已经落地，A/B 实测也拿到了真差异：

| 时刻 | 旧版战列距敌 | 新版战列距敌 |
|---|---|---|
| t=24 s | 23.7 km | **27.6 km** |
| t=30 s | 20.3 km | **25.8 km** |

**但这 4~5 km 在 3/4 远视角下只有几个像素。** 数值改了、观感没改 ——
这就是玩家说"看不出来"的原因。

⇒ 这一轮**一个战斗数值都不动**，只改镜头：
把「两军各站一边 → 主力压上」这件事用镜头语言讲一遍。

---

## 二、三拍设计

总量 **2.0 秒**，三拍缓动各不相同 —— 这是「有电影感」和「镜头乱飞」的分界。

| 拍 | 时间 | 内容 | 缓动 | 作用 |
|---|---|---|---|---|
| ① 拉高 | 0.00→0.80s | 俯角 0.72→0.95，视距 +11%，焦点移到两军包围盒中点 | out-quad（快起慢收） | 把"两军各站一边"摆给玩家看 |
| ② 定住 | 0.80→1.20s | 几乎静止（俯角回落 4%） | 线性 | **0.4 秒停顿**。没有它三拍会糊成一段连续运动，"对峙"读不出来 |
| ③ 俯冲 | 1.20→2.00s | 俯角 →0.64，yaw →-0.34，视距推近（≤1.55 倍） | smoothstep（慢起→加速→稳收） | 从高空斜切进接触线，落地即接战 |

### 参数表

| 常量 | 值 | 依据 |
|---|---|---|
| `BATTLE_SHOT_SECONDS` | 2.0 | 用户定案 |
| `SHOT_KEY_PULL` / `SHOT_KEY_HOLD` | 0.80 / 1.20 | 三拍 4:2:4 的节奏 |
| `SHOT_PULLBACK_ZOOM` | 0.90 | **从 0.74 改上来的**，见第四节坑② |
| `SHOT_PITCH_WIDE` | 0.95 | **从 1.05 改下来的**，同上 |
| `SHOT_PITCH_PUSH` | 0.64 | 比默认 0.72 更低 = 更贴地，压迫感来自这里 |
| `BATTLE_VIEW_YAW` | -0.34 | 沿用旧值（≠ 默认 -0.58，否则"转了等于没转"） |
| `BATTLE_VIEW_ZOOM` | 1.55 | 沿用旧值，现在是**上限**而非定值，见坑③ |
| `SHOT_SKIP_AFTER` | 0.15 | 玩家输入可打断的最早时刻，见坑④ |

### 为什么运镜期间 sim 照跑（不暂停）

暂停 2 秒 = 白送 2 秒看空镜，TTK 一点没变，纯亏。
照跑的话：俯瞰拍里能看到双方接近与首批曳光，俯冲拍落地即接战 —— 节奏反而更紧。

⇒ **TTK / 输出 / 命中率全部不变**，这一轮只碰相机。

## 三、实测

### 节奏量化（帧间像素差，mean abs diff）

| 区间 | 差值 | 读法 |

| 0.0→0.4 | **21.83** | 快起（拉高最猛的一段） |
| 0.4→0.8 | 8.67 | 减速收尾 |
| 0.8→1.2 | **6.22** | 最慢 = 停顿拍成立 |

## 四、踩到的四个坑

### ① 六张截图字节数完全一样（探针本身错了）

第一版在同一个协程里 `await frame_post_draw` 连拍 6 张，
结果 6 个 PNG 的**全像素 diff = 0**，而相机 `global_position` 明明每张都在变。

⇒ 是**读回拿到了同一帧的纹理**。改成「一帧只推进一步、只在 `_process` 里推进」后正常。
（`tools/probe_battle_shot.gd` 文件头把这条钉住了。）

### ② 拉远过头 / 俯角过大：船变成芝麻和棋子

第一版 `SHOT_PULLBACK_ZOOM = 0.74` + `SHOT_PITCH_WIDE = 1.05`：
视距 23.9 → 32.3，5 艘船在 1080p 上只剩 **~40px**，画面读起来是"几个小点"，
"两军"完全看不出来。

⇒ 战场本来就这么大，**拉远不产生信息量，只会把船变小**。
改成 0.90 / 0.95 后船回到 60~70px，而"各站一边"靠俯角（视线垂直化 ⇒ 纵深被摊开）表达。

### ③ 死推 1.55 倍会把侧翼切出画幅

旧版开战镜头是"zoom ×1.55"，但那时**跟随仍在跑** —— 跟随会把 `max_range`
从部署带的 52 压到 20 出头，两个东西叠加才得到玩家熟悉的效果。

运镜期间跟随被屏蔽、`max_range` 冻结 ⇒ 只剩 1.55 那一下，**推过头**：
探针实测 5 艘船里有 2 艘直接出画（画外的船还在打，玩家会以为它被秒了）。

⇒ 拍③ 的终点距离加了一条兜底：

```
dist_end = clamp(dist0 / 1.55, dist_fit, dist0)
```

`dist_fit` 与 `_process` 跟随**同一口径**（`_fit_range()`：包围盒 + `CAMERA_MIN_HALF_*`
+ `CAMERA_FIT_SCALE`）。大编队照样推满 1.55，小编队自动收手。

### ④ 玩家一动手就该跳过，但 0 秒跳过会把运镜当场掐死

运镜 2 秒对"每回合都点开战"的老玩家是负担，所以加了"输入即结束"。
但**开战那一下本身就是左键按下**（点按钮）—— 防抖设成 0 的话，
运镜会被同一个点击掐死，症状是"开战镜头从来没演过"，
而且**只在用鼠标点按钮时复现、用快捷键开战时正常**。⇒ `SHOT_SKIP_AFTER = 0.15`。

### 断言口径的变化（为什么改）

| 旧断言 | 新断言 | 原因 |
|---|---|---|
| 开战瞬间 zoom ×1.55 | 先验 `battle_shot_active()` + 时长 2.0s，再手动快进验终点 | 推近现在发生在最后 0.8 秒 |
| `_target_yaw == BATTLE_VIEW_YAW` | `yaw ≈ BATTLE_VIEW_YAW` + `_target_yaw` 为 NAN | `drive_pose` 不走收敛，target 是 NAN |
| — | **"不切船"**：终点距离 ≥ 取景下限 | 这是运镜唯一会真正伤到玩家的地方 |

## 六、没做的事（以及为什么）

**「主将环绕」没有做。** 战列环绕会让自己角速度飙升、`tracking` 跟不上 ⇒ 命中率暴跌，
与「战列要打得到人」直接矛盾。EVE 里也是小船绕大船，不是大船绕大船。

**更长的对峙（`deploy_standoff_ratio` 1.15 → 1.5）没有做。** 那会把 TTK 拉长 5~8 秒，
用户这轮明确要的是"不改数值的表现层"。
