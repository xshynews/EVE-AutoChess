## 一、病根（一句话）

**工具画的轴方向 ≠ 游戏里的舰艏方向，差了整整一层 `AXIS_REMAP`。**

| 侧 | 算式 |
|---|---|
| 游戏（`eve_ship_visual._build_hull_model`） | `舰艏世界方向 = R_y(−90°+θ) · M · bow_model`，`M = AXIS_REMAP` |
| 工具（38 轮及以前） | `轴体红球方向 = bow_model`　← **M 这一层整个丢了** |

本库 **47 艘**的 `AXIS_REMAP` 恰好等于 `−X,+Y,−Z` 这个**含 180° 的矩阵**
（`−X` 那一行就是那个 180°）。于是同一个 `bow:+X`：

```
游戏里： M·(+X) = −X  →  R_y(−90°)  →  −Z  = 朝敌 ✅
工具里： 红球画在 +X                        ⇒ 用户看到"舰艏在 +X"
用户就把它改成 −X：
游戏里： M·(−X) = +X  →  R_y(−90°)  →  +Z  = 背敌 ❌
```

⇒ 用户是在**反的参照系**里标定的。20 艘"被改反"全由此而来。

**为什么 `validate()` / `probe_bow_align` 都没抓到**：它们测的是
① 表内部自洽（正交 / det=+1 / 与 remap 反解一致）② 运行时 quaternion。
**没有任何一条断言在问「工具画面 vs 游戏画面是不是同一个方向」**。

### B 类（2 艘）—— 建议**保留**

改的是 `up`，且 `bow` 未动 ⇒ 舰艏世界方向不变（仍 −Z 朝敌），
只影响"船背朝向"。**这是有效修正**，不是被误导的。

| 船 | 源码 | 姿势表 | 舰艏世界方向 |
|---|---|---|---|
| kestrel | `bow:+Y up:+Z` | `bow:+Y up:−Z` | −Z ✅ 不变 |
| slasher | `bow:+Y up:+Z` | `bow:+Y up:−Z` | −Z ✅ 不变 |

> ⚠️ 但注意：这两艘的 `up` 从 `+Z` 改成 `−Z`，意味着**船背**从世界 `+Y` 翻到 `−Y`
> ⇒ 船会**肚皮朝天**。
> `kestrel` 的 `up:+Z` 是 23 轮**实机终审**过的真值（用户确认"茶隼没有肚皮朝天"）；
> `slasher` 是 24 轮随 kestrel 同款翻案。
> **⇒ 这两条强烈建议也作废**（除非你实机看到它们确实该翻）。
